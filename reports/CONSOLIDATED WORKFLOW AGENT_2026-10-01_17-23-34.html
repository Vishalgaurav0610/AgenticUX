Visualization Prompt (for Gemini)

     

Copy the tables above together with the prompt below and paste both into Gemini to generate the full diagram.

     
INSERT: one line only - "Consolidated Workflow for [Project Name], [User Type], [Variation]." You are creating a single end to end workflow diagram from structured data. Use only the Screen Inventory table, the Screen Relationships table, and the Cross-User Handoffs table provided alongside this prompt as your data source. Do not invent, rename, or add any screen, action, or transition that is not present in those tables. Every From Screen and To Screen value already includes its Screen ID and Name, and an Owner prefix when more than one Owner is present, so use these exactly as given for card labels. Layout: group the primary path, meaning Unique screens only, in the order given by the Forward-type rows of the Screen Relationships table, into rows of five to six screens each. Give each row a short section heading naming the phase it covers, for example Primary Flow, then Continuation, then any further phase. Connect screens left to right within a row using solid arrows labeled with the Action or CTA text from the Screen Relationships table. Use the Flow Type column to decide arrow style everywhere in the diagram: draw every Forward transition as a solid blue arrow, and draw every Backward transition as a dashed gray arrow, including retries, cancels, and error recovery loops. Label every connecting line, forward or backward, with its Action or CTA text, so a line never appears unlabeled. When a transition's From Screen and To Screen have different Owners, meaning a cross-persona handoff, draw a connecting line directly between those two screens across their sections, styled by its Flow Type like any other transition, so the cross-persona flow is visible on the diagram itself and not only listed in the Cross-User Handoffs table. For every Sub, Pop-up, or Error screen attached to a primary screen through a From or To relationship pointing at it, draw it as a smaller card directly beneath that primary screen, connected by a short labeled line, using its Screen ID and Name, and connect it back into the primary flow using the Action or CTA and Condition / Annotation text from its relationship row. If a screen in the Screen Inventory table has no matching row in the Screen Relationships table, meaning no incoming or outgoing transition, do not force it into the main flow. Place it instead in a separate box labeled Additional Recovery States, from workflow inventory, to the side of the diagram, so nothing is silently dropped and nothing is force connected. Styling: primary screens use a light blue card, sub-screens use a light gray card, pop-ups use a light yellow card, error states use a light pink or red card. Include a small Workflow Summary box using the exact numbers from the Screen Count block, meaning Unique, Sub, Pop-up, Error, and Total. Include a legend explaining the four card colors and the two arrow types. For each screen card, add two to four short action bullets that plausibly summarize what a user does on that screen, based on the screen name and the Action or CTA labels connected to it in the Screen Relationships table. These bullets are illustrative labels only, not literal source content. Title the diagram using the User Type and a short description of the flow, and add a one line subtitle describing the start and end of the flow.
